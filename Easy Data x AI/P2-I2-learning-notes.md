# P2：Agentic RAG 产品设计

本课把“AI 答得不好”拆成可诊断的问题：先看数据和检索，再看模型与业务规则。重点是 RAG 的检索范围远超向量搜索，产品需要设计完整流程与归因方法。

## RAG 不等于向量库加 LLM

RAG 的核心是 Retrieval：生成前从外部取回证据。检索可以是全文、向量、标量过滤、知识图谱或 API；向量擅长语义相近，错误码、版本号等精确内容需要全文检索，权限和时效要用元数据过滤。生产系统需要按问题组合检索通道，不能让单一向量搜索独占召回。

![RAG 中语义、全文与过滤等检索路径汇合](https://raw.githubusercontent.com/datawhalechina/easy-data-x-ai/main/docs/public/images/pm/P2/P2-05.png)

## 传统 RAG、Agentic RAG 与产品链路

传统 RAG 可以有改写、路由、重排等复杂步骤，但流程通常预先设定、无环；Agentic RAG 会根据中间结果决定是否重试、补搜、改路由或调用工具。完整产品链路包括数据准备、问题理解与改写、召回、融合重排、上下文与答案生成、评估反馈。每一步都应有可验证的质量标准。

## 三层归因与决策树

用户说“AI 答错了”只是症状。若知识库没有答案，是数据覆盖问题；有答案但没检索到，是检索策略问题；检索到正确内容却编造，是模型幻觉；事实正确但不合规或风格不适配，则是业务规则问题。先还原问题与回答，再依次检查知识是否存在、是否被检索、模型是否正确使用证据，最后匹配解法，避免把数据问题误诊为换模型。

# I2：向量数据库与 RAG

本课讲向量检索、RAG 取舍、评测和选型。

## Embedding、距离与索引

Embedding 将内容映射为向量。余弦比较方向，点积受模长影响，L2 衡量空间距离；归一化后点积与余弦等价。精确 KNN 是基线；ANN 用 HNSW、IVF 或量化提速。更换模型后须重算历史向量。

## RAG 数据与检索链路

数据需保留原文、来源、版本、权限和向量。离线解析、切分、建索引；在线多路召回、过滤重排、组装上下文并生成。Chunk 太小会割裂语义，太大则主题混杂；可按标题段落切分并保留来源位置。

向量检索擅长语义，全文检索补足错误码等精确词项，标量过滤落实权限和版本。多路结果可用 RRF 按排名融合，再按需重排；权限应在召回阶段生效，避免越权或过滤后候选不足。

## 评测与选型

Recall@K 看相关文档是否进入前 K，MRR 看首个相关结果名次，nDCG 评估分级排序；还要测忠实度、延迟、成本和权限。数据库选型看真实负载。

## 课后思考&行动

**题目**：用 30 篇以上文档和 20 条标注问题比较三种检索；调整 Chunk、ANN 参数，记录指标并验证过滤。

我用 31 篇课程稿和 20 条问题完成实验。400 字 Chunk 时三路 Recall@5/10 分别为 0.875、0.900、1.000；800 字 Chunk 的混合 Recall 为 0.925、MRR 为 0.813。调高 `ef_search` 未改变 Recall，过滤未发现违规。见[实验汇总](experiment/report.md)。

距离函数需匹配模型；精确 KNN 衡量 ANN 损失；后过滤有越权风险；换模型要重算向量；Recall 提升不保证答案更好；选型还看规模与运维成本。
